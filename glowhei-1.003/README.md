# 星霞黑体 GlowHei

屏幕显示用的中文黑体，与星霞宋体成对。字符集到 GBK（CP936）级，另附 CJK 扩展 A
的缺字回退。每个字符集有比例与等宽两款，字形与度量完全相同，区别只在
`isFixedPitch` 与 PANOSE 两个标志位。ASCII 一律半角（0.5 em），全角一律 1 em，
字体只有这两种宽度。

行距 1.141 em，与星霞宋体相同，两款可以混排或互换。

## 这里有什么

| 文件 | 内容 |
|---|---|
| `GlowHei-GBK.ttc` | GBK 全集，比例与等宽两款 |
| `GlowHei-GB2312.ttc` | GB2312 级，两款 |
| `GlowHei-ExtA.ttf` | CJK 扩展 A 的缺字回退 |
| `src/` | 构建管线的全部源码 |

整份为 SIL OFL 1.1，全文见 `LICENSE`，上游声明也在其中。

字体的 `fpgm` 表内含 Chlorophytum 的运行时函数库，该工具为 MIT，全文见
`LICENSE-MIT`。

fontconfig 配置 `65-glowhei.conf` 与自查脚本 `check-fontconfig.sh` 不在这份下载
里，它们在发布页的根目录——装不装字体都用得上，因此没有跟着字体走。

## 装上

Linux：

```sh
mkdir -p ~/.local/share/fonts
cp GlowHei-GBK.ttc GlowHei-ExtA.ttf ~/.local/share/fonts/
fc-cache -f
```

`fc-cache -f` 不能省。配套的 fontconfig 配置用一条扫描期规则修正等宽分类，而字体
列表建自扫描缓存，不重建缓存的话旧判定会留着。

Windows：右键安装 TTC。

## hinting 与体积

成品带 hinting，占体积的将近一半。汉字、假名走 Chlorophytum，拉丁、希腊、西里尔走
ttfautohint——两套工具各自处理它有模型的那部分，在各自的字体里生成，最后按码点合并。
**每一个有墨的字形都带指令**，此前 Chlorophytum 的配置按 Unicode 区块取舍，制表符、
方块元素与其它符号是漏掉的。补上之后又按实测（同一字形在 FreeType 上"加提示不许比
不加提示更浅"，全码位 12/16/22px 逐个跑）**暂时空着三段**：`U+2500–U+25FF`（制表符、
方块元素、几何图形），以及**横杠/破折号类**与**小记号类**——**整类禁用，一个不落，共 72 个码位**
（名单见 `build/hint.py` 的 `UNHINTED_SYMBOLS`，由 `CLASS_PATTERNS` 生成）。
整类而不是逐点，是因为逐点会做出"这根横杠hint、旁边那根不hint"的不一致；
代价是**55 个本来没失败的同类字形也一并空着**（实测 0 个失败），这是为同类
字形渲染一致付的。三类都是"又薄又孤立的墨"被模型压扁或推到
两像素之间——**这是"今天这个模型在这三个尺寸下净负收益"，不是"这些字形不该 hinting"**。

**拉丁、希腊、西里尔字母与其它符号不受影响**，实测失败率 0.5–0.8%，与这三类的
18–35% 差着一到两个数量级；四个孤例（`ш` `Ю` `∥` `∣`）留在原地。

收益集中在 12px 及以下的密集汉字：横画不粘连、笔画数可辨。判据是形状忠实度而非
对比度——以同一轮廓在高分辨率下渲染再降采样为基准，Chlorophytum 是各方案中最忠实
的一个，且比不加 hinting 更忠实。

只在大字号用字、或要把字体嵌进文档而在意体积，可以去掉：

```sh
make -C ../sbitgraft-1.003
../sbitgraft-1.003/sbitgraft --strip GlowHei-GBK.ttc GlowHei-GBK-nohint.ttc
```

轮廓、度量、字符映射与命名都不会被改动。

## 字形来源

轮廓取自 Sarasa Fixed SC（更纱黑体），其汉字来自思源黑体、拉丁来自 Iosevka。本项目
做的是子集化到 CP936、upem 降到 256、逐字择优简化、把超出行框的字形缩回去，以及重新
度量、命名与 hinting。

**三十个 CP936 双字节符号是例外，它们另取自思源黑体。** 这批符号（`ˊ ˋ ˙ ‐ – ― ‥
‵ ℅ ℉ ℡ ↖ ↗ ↘ ↙ ∕ ∟ ∣ ≒ ≦ ≧ ⊕ ⊿ ▼ ▽ ◢ ◣ ◤ ◥ ☉`）在 CP936 里各占两个字节，
按本项目「双字节即整格」的规则应当是 1 em，而 Sarasa 把它们画成了半格；同一个源给
顿号 `、` 的却是整格。宽度改了字形也得跟着改，否则整格里会放着一个半格宽的小字。
思源黑体是 Sarasa 汉字本身的来源，取它不会脱节。思源黑体为 SIL OFL 1.1，声明同样
写在字体的版权信息里。

**制表符、方块元素与旁边的几何图形同理，共 169 个，也取自思源黑体。** 这一批比上面
那 30 个多一层要求：它们不只是占满一格，还要**接得上**——连排画框时竖线必须跨行相
连。所以它们保留源字体的水平位置（居中会让 `┌` 离开它要接的那条边），纵向则映射到
本项目的行框上，笔画因此能一直连下去。几何图形（`■ ▲ ○ ◆` 等 9 个）不拼接，按普通
符号居中摆放。

**思源黑体的制表符笔画只有 40 单位（0.04 em，22px 下不到一个像素），取用时按轴加粗
到本项目的 70/140**，否则 16–22px 下竖线会渲染成浅灰而横线是实心黑，一个框看着就
是断的。加粗在规则自己的中心线上进行，两个方向与单线/双线因此重量一致。

**一条使用上的变化：表格要用全角空格填。** 规则现在是整格，而 ASCII 空格仍是半格
（本字体给每个 ASCII 半格），所以用 ASCII 空格对齐的表格线不再对得齐；用全角空格
（U+3000）填则完全对齐。

`src/` 下是完整的构建管线。简化一步需要 FontForge，以及本机的 `freetype-py` 与
`Pillow`——后两者用来渲染比对每个字形简化前后的形状，偏差超过 1% 的拟合一律退回。
这个检查不是可选项：缺了其中任何一个，整步跳过而不是放宽标准。hinting 需要
Chlorophytum 与 ttfautohint。两步都缺只是产物更大，构建不会中断。
